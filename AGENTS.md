# AGENTS.md

## Feature parity: the first rule

Hairline does the same in every agent it supports: Claude Code (`claude/`) and Pi (`pi/`). A change to what the line shows or does lands in all of them in the same PR, with tests in each. A PR that changes one agent alone does not merge. A host that cannot do a feature at all, such as Pi with no transcript render hook, is the only exception, and the PR names the missing host API.

The Claude desktop app never asks for `PromptHint`, so hairline draws there in `AbovePrompt`. `drawLine` serves both; `monospace` restyles hairline's text for the app.

## Names

One name for each area of the line, the same in code, comments, tests, PRs and talk, in both agents.

| Name | The area |
|---|---|
| context bar | the bar across the terminal: the context fill, its percent where the fill ends, the auto-compact mark |
| workspace | the repository, the worktree and the branch, left on the row under the bar |
| activity | what Claude is doing: thinking, writing, a tool. scan shows it on the bar, middle in the row |
| scan | the layout where a light runs along the context bar while Claude works |
| middle | the layout where the activity sits in words in the middle of the row |
| limits | 5h and 7d on the right of the row, and the extra usage spend from 95% of a window |
| model | the model, the effort and the session ID after the limits |
| ledger | the rows a click on the limits opens: cost, tokens, turns, limits |
| token split | `in / out / read / write` in the ledger |
| picker | the rows a click on the model or the effort opens |

## Check

```sh
claude plugin validate .
claude plugin test .
```

CI runs both on Claude Code 2.1.312 (Node 22). `main` requires the `check` status. Raise the pin only on purpose.

## Hooks

- `.claude-plugin/plugin.json` names `claude/hooks.json` in `hooks`: Claude Code reads `hooks/` only when the manifest names no path. `claude/hooks.json` loads `claude/register.tsx` only. `claude/readout.tsx`, `claude/graph.tsx`, `claude/bar.tsx`, `claude/spinner.tsx` and `claude/chip.tsx` are Client modules. Keep them out of `hooks.json`.
- The desktop app draws a `Button` as a native control in its own font. `chip.tsx` stands in for one there and posts clicks to `ui.message`.
- Register each event once, or each time with its own matcher. A second `on` of the same event without one throws.
- Spell `on`, `$`, `$.env` and `$.state` literally. Pass `$` only to module-level functions.
- No `import()`, `require`, Node or DOM. Use `$.process`, `$.http`, `$.store` and `$.clock`.
- `/reload-plugins` resets module state without `session.start`, so the first render calls `load($)`.
- Animate in Client modules. Hint-line redraws stop at 30 a second, the surface clock does not.
- Colors come from `ansi256(n)` with n below 16 on the terminal, or theme keys elsewhere. Never hex.

## Pi

- `pi/index.ts` is the Pi extension, loaded through `pi.extensions` in `package.json`. It replaces Pi's footer with `ctx.ui.setFooter`.
- `pi/line.ts` draws the footer as text with SGR codes for the 16 palette slots. `pi/anim.ts` ports `readout.tsx` and `graph.tsx`. Both run under `node --test` without the Pi host.
- A change to the line in `claude/` needs the same change in `pi/`, in the same PR. See Feature parity.
- Pi tests live in `pi/tests.ts`. A `*.test.ts` name would make `claude plugin test` run them with the Claude Code test kit.
- Check with `npm ci`, `npm run typecheck:pi` and `npm run test:pi`. CI runs them after the Claude Code steps.
- Bump `version` in `package.json` on a behavior change of the Pi extension.

## E2E

`scripts/e2e.py` (Claude Code) and `scripts/pi-e2e.py` (Pi) drive real sessions in a pseudo-terminal and check the context bar, the workspace, the token total and the model, before and after one turn. `scripts/e2e_kit.py` serves a fake Anthropic Messages API, so no API key is needed. `scripts/e2e_line.py` holds the checks both share. Run from the repo root, after `npm ci` for Pi:

```sh
uv run --no-project --with pyte --with pywinpty python -I scripts/e2e.py      # Windows; ptyprocess on Linux
uv run --no-project --with pyte --with pywinpty python -I scripts/pi-e2e.py
```

Screens land in `scripts/e2e-out/`. The `e2e` workflow runs both on Linux for changes to `claude/`, `pi/` or `scripts/`, with the pins of `ci.yml` and `package.json`.

## Types

`.claude-plugin/types` is generated by `claude --plugin-dir .` and gitignored. Do not edit or commit it.

## Ship

- Conventional Commits. One PR per change, CI green, rebase merge.
- Size each PR as a release and bump `version` in `plugin.json` and `package.json` in the same PR:
  - MAJOR: a breaking change, marked `!` in the type. Examples: a removed or renamed setting or key, a changed command, a raised `engines` or Pi peer range.
  - MINOR: `feat`, something users can see or do that is new.
  - PATCH: `fix` or `perf`.
  - No bump: `docs`, `ci`, `test`, `chore` or `refactor` with no change users see.
- Bump `package.json` with sed, plus the two `version` lines of `package-lock.json`: `npm version` reformats inline arrays.
- The merge of a PR that raises the version runs `publish.yml`: it tags `hairline--v<version>` with `claude plugin tag --push`, creates the GitHub release and stages the version on npm. A maintainer approves the stage with 2FA on npmjs.com. Do not tag or release by hand.
- Comments say why, never what.
- README images come from `tests/screenshots.test.ts`. The `screenshots` workflow renders them on `main` and pushes them to the `screenshots` branch.
- Keep each file's line endings. Source files and `plugin.json` are CRLF. Other JSON and YAML files are LF.
