# AGENTS.md

The Claude desktop app never asks for `PromptHint`, so hairline draws there in `AbovePrompt`. `drawLine` serves both; `monospace` restyles hairline's text for the app.

## Check

```sh
claude plugin validate .
claude plugin test .
```

CI runs both on Claude Code 2.1.312 (Node 22). `main` requires the `check` status. Raise the pin only on purpose.

## Hooks

- `hooks/hooks.json` loads `hooks/register.tsx` only. `hooks/speed.tsx`, `hooks/spinner.tsx` and `hooks/chip.tsx` are Client modules. Keep them out of `hooks.json`.
- The desktop app draws a `Button` as a native control in its own font. `chip.tsx` stands in for one there and posts clicks to `ui.message`.
- Register each event once, or each time with its own matcher. A second `on` of the same event without one throws.
- Spell `on`, `$`, `$.env` and `$.state` literally. Pass `$` only to module-level functions.
- No `import()`, `require`, Node or DOM. Use `$.process`, `$.http`, `$.store` and `$.clock`.
- `/reload-plugins` resets module state without `session.start`, so the first render calls `load($)`.
- Animate in Client modules. Hint-line redraws stop at 30 a second, the surface clock does not.
- Colors come from `ansi256(n)` with n below 16 on the terminal, or theme keys elsewhere. Never hex.

## Pi

- `pi/index.ts` is the Pi extension, loaded through `pi.extensions` in `package.json`. It replaces Pi's footer with `ctx.ui.setFooter`.
- `pi/line.ts` draws the footer as text with SGR codes for the 16 palette slots. `pi/anim.ts` ports `slot.tsx` and `speed.tsx`. Both run under `node --test` without the Pi host.
- A change to the line in `hooks/` needs the same change in `pi/`, or a reason in the PR why Pi differs.
- Pi tests live in `pi/tests.ts`. A `*.test.ts` name would make `claude plugin test` run them with the Claude Code test kit.
- Check with `npm ci`, `npm run typecheck:pi` and `npm run test:pi`. CI runs them after the Claude Code steps.
- Bump `version` in `package.json` on a behavior change of the Pi extension.

## Types

`.claude-plugin/types` is generated by `claude --plugin-dir .` and gitignored. Do not edit or commit it.

## Ship

- Conventional Commits. One PR per change, CI green, rebase merge.
- Bump `version` in `.claude-plugin/plugin.json` on a behavior change.
- Comments say why, never what.
- README images come from `tests/screenshots.test.ts`. The `screenshots` workflow renders them on `main` and pushes them to the `screenshots` branch.
- Keep each file's line endings. Source files and `plugin.json` are CRLF. Other JSON and YAML files are LF.
